# Мониторинг сетевого трафика «ТехноПрофи»

Самостоятельная работа по лекции 07 дисциплины «Информационная безопасность бизнес-процессов». Python-прототип сохраняет формат записей из лекции и анализирует политики портов, активность вне рабочего времени, сканирование портов, внешний трафик, распределение по протоколам и объём по отделам.

| Задание | Результат |
| --- | --- |
| 1. Анализ и улучшение | Обнаружение возможного DDoS по PPS, журнал аудита с проверкой целостности, оповещения в Telegram и Slack |
| 2. Бизнес-кейс | [Расчёт ROI](docs/roi.md) и калькулятор с тремя сценариями |
| 3. Интеграция | [Настройка адаптеров](docs/integrations.md) для биометрического провайдера, AWS, Azure, MISP и OTX |

## Запуск

Требуется Python 3.11+. Для IANA-часовых поясов на Windows установите `python -m pip install tzdata`, если в системе отсутствует их база. Команды для PowerShell:

```powershell
$env:AUDIT_KEY_HEX = python -c "import secrets; print(secrets.token_hex(32))"
python -m traffic_monitor monitor --demo --output report.json
python -m traffic_monitor verify-audit
python -m traffic_monitor roi
```

Используйте один и тот же ключ для записи и проверки конкретной базы. Новый ключ подходит для нового файла базы, который можно задать параметром `--audit-db ПУТЬ` перед подкомандой.

Демонстрация создаёт 13 600 синтетических записей. В отчёте появляется один `SUSPECTED_DDOS` в направлении `192.168.1.10`: 1 200 пакетов/с на протяжении 3 секунд, 40 источников в секунду. Журнал фиксирует старт, инцидент и итог прогона. Внешние вызовы активируются флагом `--deliver`.

### Анализ CSV

```powershell
python -m traffic_monitor monitor --csv traffic.csv --pps 1000 --sources 10 --seconds 2 --timezone Asia/Vladivostok --output report.json
```

```csv
timestamp,source_ip,destination_ip,protocol,port,size_bytes,department
2026-11-16T13:02:15.123+10:00,203.0.113.2,192.168.1.10,HTTPS,443,120,IT
```

Строка представляет один наблюдённый пакет. Метки без смещения относятся к часовому поясу `--timezone`; он также задаёт рабочие часы и границы отчётного дня. `--internal-network` можно указать несколько раз для свойств сети. По умолчанию используется `192.168.1.0/24`. Прототип анализирует пакетную выгрузку целиком; агрегированные записи NetFlow требуют предварительного преобразования с сохранением количества и времени пакетов.

### Правило DDoS

1. Метод группирует пакеты по адресу назначения и секунде UTC. В каждом односекундном окне PPS равен числу пакетов.
2. При PPS ≥ 1 000 и ≥ 10 уникальных адресах источника в течение двух последовательных секунд формируется один инцидент `SUSPECTED_DDOS`. Соседние окна одного типа объединяются, сохраняются пик PPS и три наиболее активных источника. Пороговое окно с меньшим числом источников классифицируется как `PPS_SPIKE` по тому же правилу длительности.
3. Пороги настраиваются по фоновому трафику и ёмкости сервиса. NAT, подмена адресов, легитимные всплески и атаки с низким PPS ограничивают точность. Для подтверждения инцидента оператор проверяет метрики сервиса и сетевого оборудования.

### Аудит и контроль целостности

Запись содержит номер, время UTC, тип события, автора, результат, ID прогона и параметры события. SQLite записывает события транзакционно. Каждая запись подписана HMAC-SHA256 с учётом подписи предыдущей, а команда `verify-audit` проверяет цепочку. Для обнаружения усечения сохраните её вывод как контрольную точку в отдельном защищённом хранилище и используйте `verify-audit --checkpoint checkpoint.json`.

| Контроль [NIST SP 800-53 Rev. 5](https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final) | Реализация и эксплуатация |
| --- | --- |
| AU-2, AU-3, AU-12 | Фиксация прогона, инцидентов, результатов интеграций и биометрических проверок. Тип, время, источник и результат доступны для разбора |
| AU-8 | Временные метки UTC; синхронизация часов настраивается на хосте |
| AU-9 | HMAC-цепочка и контрольные точки; права доступа к файлу, внешнее хранение точек и хранение ключа настраивает оператор |
| AU-11 | SQLite хранит записи между запусками; срок хранения, архивирование и удаление задаются политикой организации |

В журнал не попадают ключи, токены, содержимое пакетов или биометрические шаблоны. Сетевые идентификаторы в инцидентах требуют ограничения доступа. Таблица описывает покрытие отдельных контролей учебным прототипом; подтверждение соответствия включает эксплуатационные процедуры и проверку организации.
